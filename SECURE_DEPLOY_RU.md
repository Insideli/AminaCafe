# Безопасный запуск AminaCafe + Paloma365

## Что изменено

- Пароли сотрудников удалены из `src/data.js` и из интерфейса админки.
- Вход сотрудников выполняется через `/api/auth`.
- После входа сервер создаёт HttpOnly-cookie: JavaScript сайта не может прочитать или подделать её.
- `/api/paloma` требует действующую сессию сотрудника и проверяет его роль.
- Синхронизация меню доступна только `admin` и `developer`.
- Отправка заказов доступна `admin`, `developer`, `waiter`, `cashier`.
- Профили сотрудников хранятся отдельно под ключом `amina_staff_profiles_v13` и не содержат паролей.

## Переменные Vercel

Добавьте для Production, Preview и Development (если используете):

- `AMINA_SESSION_SECRET` — генерируется локальным файлом `tools/staff-config.html`.
- `STAFF_ACCOUNTS_JSON` — генерируется тем же файлом; содержит только хэши паролей.
- `PALOMA_AUTHKEY` — новый ключ Paloma365.
- `PALOMA_HOST` — `https://api.paloma365.com`.
- `PALOMA_POINT_ID` — ID правильной торговой точки; можно добавить после первой проверки связи.

После изменения переменных всегда делайте новый Deploy: старые deployments не получают новые значения.

## Важная очистка Firestore

После успешного развёртывания новой версии удалите старый документ:

`amina_db / amina_roles_v12`

В нём могли остаться старые открытые пароли. Новая версия его не использует.

Не удаляйте новый документ:

`amina_db / amina_staff_profiles_v13`

Он содержит только имена, роли, графики и статусы сотрудников.

## Ограничение текущего этапа

Paloma защищена серверной сессией, но основная бизнес-информация приложения всё ещё читается и изменяется клиентом через Firestore. Перед полноценным запуском кафе нужно отдельно настроить Firebase Authentication и Firestore Security Rules для заказов, столов, клиентов и персонала.
